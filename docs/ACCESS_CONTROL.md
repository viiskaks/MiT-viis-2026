# Доступ к общему пространству

## Что изменилось

Раньше приложение сохраняло данные в LocalStorage: посетитель редактировал свою
копию, а не данные ментора. Теперь браузер получает общие данные из API. При
недоступном API редактирование не переключается обратно на LocalStorage.

Пространство закрыто для анонимных посетителей. Статические JS/CSS и исходники
по-прежнему публичны; встречи, Zoom-ссылки, аккаунты и введённые материалы не
включаются в сборку. Все вошедшие участники видят общие материалы и заметки встреч;
это одно пространство, не система раздельных групп.

| Действие                                           | Владелец                 | Менти                       | Без входа        |
| -------------------------------------------------- | ------------------------ | --------------------------- | ---------------- |
| Читать общие встречи, программу, профиль           | Да                       | Да                          | Нет              |
| Создавать/менять/удалять встречи и материалы       | Да                       | Нет                         | Нет              |
| Импорт, сброс, настройки, общий JSON-экспорт       | Да                       | Нет                         | Нет              |
| Создавать аккаунты, менять права, отключать доступ | Да                       | Нет                         | Нет              |
| Сохранять личный прогресс                          | Общий ориентир программы | Только с разрешения ментора | Нет              |
| Симулированный терминал                            | Да                       | Да                          | Нет в интерфейсе |
| Менять собственный пароль                          | Да                       | Да                          | Нет              |

Терминал — локальная игрушка: он не выполняет команды ОС и ничего не записывает
на VPS. Скачанный JavaScript можно запустить самостоятельно; контролировать это
не требуется для защиты серверных данных. Разрешение «личный прогресс» относится
к серверным записям, а не к возможности запускать JS в собственном браузере.

## Почему не hardcoded users и не секрет в React

Код браузера доступен посетителю. Проверка роли только в интерфейсе, пароль в
`VITE_*` или флаг в LocalStorage не защищают API. Здесь роль загружается из SQLite
при каждом запросе. Нет открытой регистрации, API выдачи роли owner или
демонстрационного пароля. Единственный владелец создаётся административной CLI.

Для небольшого пространства на собственном VPS выбран Node.js + SQLite, без
облачного аккаунта и внешней зависимости для входа. Большему сервису подойдёт
OIDC-провайдер с MFA/Passkeys; интеграция с существующим провайдером — следующий
шаг, а не второй параллельный механизм паролей. Встроенный `node:sqlite` в Node 24
помечен release candidate; используется небольшой набор синхронных операций.
Один экземпляр API и локальный Docker volume достаточны для этой нагрузки.

## Защита

- Случайные 256-битные сессии; в БД только SHA-256 токена, срок 8 часов.
- В production cookie `__Host-mit_session`, `HttpOnly`, `Secure`, `SameSite=Strict`,
  `Path=/`, без Domain. Пароль и токен не сохраняются в LocalStorage.
- HTTPS обязателен; HTTP разрешён только с origin localhost/127.0.0.1 для разработки.
- На изменяющих запросах точное совпадение Origin с APP_ORIGIN, JSON Content-Type;
  CORS не разрешается. Origin не строится из присланного Host/X-Forwarded-Host.
- Пароли 14–128 символов, уникальная соль и scrypt (N=32768, r=8, p=3).
- Лимит попыток по аккаунту и сетевому peer сохраняется в БД; Nginx дополнительно
  ограничивает login по реальному IP. Не доверяем присланному X-Forwarded-For.
- Общие записи изменяет только owner. Личный прогресс привязан к ID текущей
  серверной сессии; клиент не может указать другого пользователя.
- Отключение пользователя, изменение разрешений и сброс пароля отзывают сессии.
- Смена собственного пароля требует текущий пароль и завершает все его сессии.
- Общая схема Zod на клиенте и сервере, лимиты размера/вложенности JSON,
  параметризованные SQL-запросы, версия записи защищает от потери правок в двух вкладках.
- Ошибка сохранения не выдаётся за успех. Конфликт 409 требует обновить данные
  и повторить правку. Автоматического объединения правок нет.

## Первый запуск локально

Нужен Node.js 24.13+ (рекомендуется актуальный Node 24 LTS):

```sh
npm ci
npm run build
```

В Bash создайте владельца: пароль вводится скрыто и не попадает в аргументы процесса.
Выберите собственный логин вместо `your-login`.

```bash
read -r -s -p 'Пароль владельца (минимум 14 символов): ' MIT_OWNER_PASSWORD
printf '\n'
printf '%s' "$MIT_OWNER_PASSWORD" | node server-dist/index.js create-owner your-login
unset MIT_OWNER_PASSWORD
npm run start:api
```

В другом терминале `npm run dev`, затем http://localhost:5174. Vite проксирует
`/api` на локальный API. По умолчанию БД — `data/workspace.sqlite`, API слушает
только loopback. Не запускайте тестовый сервер из tests в production.

## Аккаунты и перенос данных

Войдите владельцем → Настройки → добавьте менти. Передайте начальный пароль
лично через доверенный канал. Менти меняет его в Настройках. Вы отдельно разрешаете
сохранение личного прогресса и можете выключить доступ целиком.

Для миграции прежних данных откройте сайт на том же устройстве и origin, где
работали раньше: Настройки → «Скачать старую локальную копию» → «Импорт JSON».
Проверьте данные перед подтверждением: импорт заменяет общие материалы для всех.
Старая копия остаётся в браузере, пока вы её не удалите через настройки браузера.
JSON не переносит пароли, аккаунты или личный прогресс; для них нужна резервная
копия всей SQLite БД. Изменение hostname создаёт другое хранилище браузера.

## Эксплуатация

Конфигурация API: APP_ORIGIN, DATABASE_PATH, LISTEN_HOST, PORT — серверные переменные,
не `VITE_*`. Runtime без root, база вне web-root, порт API не публикуется наружу.
Нужны HTTPS reverse proxy `/api/`, устойчивый volume, резервные копии и обновления
Node/образов. Инструкции конкретного VPS хранятся в приватном инфраструктурном репозитории.
Текущий workflow статических файлов не разворачивает API: его нужно поднять отдельно.

Для восстановления владельца используйте ту же CLI `reset-owner` со скрытым вводом
через stdin и той же DATABASE_PATH. Это действие доступно администратору VPS,
не публичному endpoint. Не коммитьте БД, JSON с персональными данными или пароли.

Ограничения: нет MFA, почтового восстановления, аудита действий, live-синхронизации,
раздельных групп или масштабирования API на несколько узлов. Блокировка не может
отозвать уже скачанную информацию. Для более широкого использования добавьте
OIDC + MFA и аудит. Это протестированный MVP, а не независимый аудит безопасности.

[Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html),
[CSRF](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html),
[Node SQLite](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html).
