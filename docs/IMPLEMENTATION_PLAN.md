# План реализации MiT-viis-2026

## Продукт

Личное пространство для знакомства ментора и менти во время Zoom-встречи. От первых архитектурных схем до собственного приложения на VPS. Первая сессия — знакомство, ожидания, проекты и безопасная игра с командами; не технический экзамен.

## MVP и допущения

Русский интерфейс. Mission Control, список встреч, редактируемое дерево программы, симулированный терминал, редактируемый профиль/проекты, настройки и JSON-резервные копии. Начальная сессия без даты/времени/Zoom URL. Все биографические данные — явно обозначенные заготовки. Один браузер — одно независимое пространство. Не публикуем сайт или remote-репозиторий.

## Выбор технологий

React + TypeScript + Vite дают статическую сборку с типизированными границами. Tailwind через Vite и собственные CSS-компоненты обеспечивают цельный визуальный стиль. Lucide — иконки. Zod проверяет импорт и LocalStorage. Luxon явно интерпретирует время в IANA timezone, независимо от часового пояса браузера. Простая hash-навигация не требует роутера или серверных rewrite. React Context и обновления immutable достаточны; сложный state manager не нужен.

Проверены первичные источники: [Vite](https://vite.dev/guide/), [Tailwind + Vite](https://tailwindcss.com/docs/installation/using-vite), [Zod](https://zod.dev/), [LocalStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage). LocalStorage привязан к origin, сохраняется между визитами и может быть недоступен; ошибки записи нужно показывать пользователю.

## Границы компонентов

- `types/workspace.ts`: модели и runtime-схемы.
- `data/seed.ts`: редактируемые примеры, 7 разделов программы.
- `lib/storage.ts`: persistence adapter; последующая замена на backend.
- `lib/time.ts`, `lib/roadmap.ts`: время, сортировка, операции над деревом.
- `hooks/workspace.tsx`: единый workspace и статус сохранения.
- `components/`: оболочка, диалоги, поля, навигация.
- `features/`: dashboard, meetings, roadmap, terminal, mentor-profile, settings.
- `tests/`: проверки данных и браузерные пользовательские сценарии.

## Декомпозиция

2. Хранилище с versioned-схемой, валидацией, экспортом, импортом и сбросом.

9. Типы, lint, unit/browser tests, production build, скриншоты и документация.

## Хранение

Один versioned JSON-документ: встречи, дерево с прогрессом, профиль, настройки. LocalStorage обновляется после пользовательского изменения. Повреждённый документ не перезаписывается автоматически. Импорт валидируется целиком до замены; замена, удаление и сброс требуют подтверждения. Экспорт — локальная загрузка JSON. Не сохраняем историю учебного терминала. Никакой синхронизации между участниками; перенос — через JSON.

Встреча хранит локальные дату/время и собственную timezone. Настройка timezone задаёт значение для новых встреч, не сдвигает старые. Несуществующее/неоднозначное время перехода DST отклоняется. Встречи без даты явно обозначены как несогласованные.

## Критерии приёмки

Навигация работает при обновлении страницы; CRUD встреч и дерева сохраняется; статусы и профиль восстанавливаются; ссылки открываются безопасно; терминал никогда не исполняет код пользователя; JSON проверяется до замены; сброс подтверждается; seed не содержит реальных дат и Zoom URL. Сборка, типы, lint и функциональные проверки проходят. Проверены ноутбук, узкая колонка рядом с Zoom и телефон.

## Обновление: закрытое общее пространство

Первоначальный LocalStorage MVP заменён серверным источником данных. Новый объём:
owner/mentee, создание аккаунтов только владельцем, разрешаемый личный прогресс,
SQLite, cookie-сессии, защита всех записей в API, перенос прежнего JSON, приватный
контейнер API. Детали решения и критерии безопасности: `ACCESS_CONTROL.md`.
Проверки: анонимные/mentee запросы не меняют общие данные; отозванная сессия
не работает; прогресс изолирован по аккаунту; серверные ошибки не имитируют
сохранение; пароль/роль из LocalStorage не влияют на права.
