# Архитектура

## Поток данных

```text
seed / LocalStorage → WorkspaceRepository.load → parseWorkspace
                                              ↓
                           WorkspaceProvider (data, saved, error)
                                              ↓
                    экраны → update / replace → parseWorkspace
                                              ↓
                                 WorkspaceRepository.save

JSON-файл → parseBackup → предпросмотр количества объектов
                       → подтверждение → replace
```

`types/workspace.ts` содержит типы и Zod-схемы: UI, загрузка и импорт используют один контракт. Запись проверяется до изменения состояния. Provider держит актуальный workspace в ref и React state, чтобы последовательные операции не работали с устаревшими снимками. В StrictMode нет эффекта, автоматически записывающего seed.

## Структура

```text
src/
  App.tsx                       hash-навигация и оболочка
  components/ui.tsx             native dialog, подтверждение, поля, progress
  data/seed.ts                  начальные примеры
  types/workspace.ts            контракт данных и валидация
  hooks/workspace.tsx           единое состояние и ошибки сохранения
  lib/storage.ts                адаптер LocalStorage, JSON export
  lib/time.ts                   Luxon, сортировка и отображение времени
  lib/roadmap.ts                immutable-операции над деревом
  features/
    Dashboard.tsx               следующая сессия и интерактивная схема
    Meetings.tsx                список и редактор встречи
    Roadmap.tsx                 рекурсивное дерево и редактор темы
    Profile.tsx                 профиль, ссылки и проекты
    Settings.tsx                backup, reset и настройки
    terminal/
      commands.ts               локальный реестр команд без DOM
      Terminal.tsx               ввод, история, вывод и таймер симуляции
  styles/index.css              responsive CSS + Tailwind
```

Контент обучения и знакомства хранится отдельно в seed, затем меняется пользователем в workspace. UI-тексты остаются в компонентах. Хеш-маршруты позволяют запускать сайт на обычном статическом сервере без роутера и fallback-правил.

## Модель данных v1

`Workspace`: `version`, `meetings[]`, `roadmap[]`, `profile`, `settings`.

- `Meeting`: идентификатор, название, локальные `date`/`time`, `duration`, `timezone`, `agenda`, `zoomUrl`, `status`, `notes`. Пустые date/time разрешены только вместе. Сортировка по UTC-моменту, бездата в конце. Предстоящей считается planned-встреча, которая ещё не закончилась.
- `Topic`: идентификатор, название, описание, статус, `children[]`. Одни и те же правила на любом уровне. Прогресс — completed-листья / все листья. Удаление раздела удаляет поддерево.
- `Profile`: заголовок, знакомство, приветствие, опыт, технологии, ссылки и проекты. Проект содержит описание, теги и необязательные repo/demo URL.
- `Settings`: timezone для новых встреч.

ID создаются через `lib/id.ts`: `crypto.randomUUID()` либо UUID v4 на `crypto.getRandomValues()` для локального LAN HTTP, где randomUUID может быть недоступен. Публичное размещение рекомендуется через HTTPS.

## Надёжность

Схемы strict: неизвестные поля/версии отклоняются, скрытого partial merge нет. URL разрешают только HTTP(S), без встроенного логина/пароля. Ссылки открываются с `noopener noreferrer`; текст выводится как React text, не как HTML. Перед рекурсивной валидацией ограничиваются размер дерева, глубина и уникальность ID, чтобы некорректный backup не вызывал бесконечный обход.

Ошибка чтения не уничтожает исходную строку LocalStorage. Обычные записи блокируются до явного восстановления/сброса. Ошибка записи показывает предупреждение, позволяет продолжить в памяти и экспортировать JSON. Миграции не требуются для первой версии; будущие версии должны получать явную миграцию до парсинга, с сохранением исходного backup.

Диалоги используют native `dialog`, focus trap, Escape и восстановление фокуса. Кнопки и поля подписаны; подсказки полей связаны через `aria-describedby`. Дерево использует обычные списки и кнопки, без объявления ARIA-tree со сложными обязательными клавишами. Терминал — live log с ограничением вывода 250 строк / истории 100 команд. Таймер симуляции очищается при выходе; reduced-motion завершает pipeline без постепенного вывода. Внешний звук и autoplay отсутствуют.

## Граница будущего backend

`WorkspaceRepository` уже отделён от компонентов. Для удалённого хранилища потребуется сделать load/save асинхронными, добавить состояния загрузки, revision/version для конфликтов и явную политику offline-правок. Это расширение Provider/adapter; UI-редакторы и модели можно сохранить. Синхронный localStorage-адаптер не выдаётся за готовую real-time архитектуру.

Совместные комнаты, роли, аутентификация, realtime, лаборатории и интеграции пока отсутствуют. Для real Linux lab нужен отдельный сервис с изоляцией процессов/сети и лимитами; текущий terminal registry к нему напрямую подключать нельзя.
