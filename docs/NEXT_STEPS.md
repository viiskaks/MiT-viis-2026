# Следующие шаги

## За один-два дня до знакомства

1. **Контент, 2–3 часа.** Написать короткое знакомство в редакторе профиля, выбрать 2–3 проекта с живыми ссылками. Для каждого: задача → схема → интересный урок. Заполнить согласованную дату и Zoom URL, проверить timezone.
2. **Репетиция, 30–45 минут.** Открыть интерфейс рядом с Zoom. Пройти маршрут: знакомство → проекты → ожидания → программа → `coffee` и `help`. Не пытаться изучить всю программу в первый день.
3. **Материалы, 1–2 часа.** Дополнить описания первых тем ссылками в виде текста и вопросами для обсуждения. Выбрать минимальную идею pet-проекта вместе с менти.
4. **Практичный небольшой релиз, 2–4 часа.** При необходимости добавить скачивание встречи в `.ics` и отдельный короткий блок ожиданий/заметок первой сессии. Это полезнее сложного календаря.
5. **Доставка, 1–2 часа.** Отдельным действием опубликовать статический `dist/` на выбранном HTTPS-хостинге, проверить браузер менти и обмен JSON. Перед обновлением — export. Публикация не создаст синхронизацию.

## После MVP: отдельные этапы

1. Реальные общие комнаты наставничества с моделью владения.
2. Синхронизированные встречи и программа: версии документов, конфликты, offline-поведение.
3. Совместная доска Excalidraw или tldraw.
4. Упражнения по сборке архитектуры в React Flow.
5. Изолированные Linux-лаборатории: отдельные контейнеры/VM, лимиты, очистка, безопасный доступ.
6. GitHub-интеграция для pet-проектов: минимальные разрешения, PR/review-процесс.
7. Заметки сессий и milestones, без тяжёлой аналитики.
8. Роли ментора и менти и понятные права на изменение данных.
9. Постоянный backend (например Supabase), резервирование и при необходимости аутентификация.

Не смешивать миграцию хранения и Linux labs в один релиз. Сначала доказать полезность обычных встреч, программы и общей доски.
