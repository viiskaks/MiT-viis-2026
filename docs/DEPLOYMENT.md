# Развёртывание

Теперь приложению нужны **статический клиент и приватный API**, собранные из одного
проверенного commit. Старый static-only деплой не запускает авторизацию.

1. `npm ci && npm run build` (Node 24.13+) создаёт `dist/` и `server-dist/`.
2. Публикуйте `dist/` обычным статическим workflow.
3. Соберите API через `docker build -f Dockerfile.api -t mentorship-api .`.
4. Подключите устойчивый volume к `/data`, задайте `APP_ORIGIN=https://mentor.example.com`.
5. Reverse proxy должен передавать `/api/` API и обслуживать остальные пути из `dist/`.
6. Не публикуйте API-порт наружу; настройте HTTPS, лимит запросов к login и отсутствие
   кеширования `/api/`. Пробрасывайте Origin и Cookie, не подменяйте их.
7. Создайте единственного владельца CLI `create-owner`, передав пароль через stdin
   в контейнер с тем же volume. Нет default users или startup-пароля в переменных браузера.
8. Войдите, импортируйте прежние данные через Настройки и создайте аккаунты менти.

`APP_ORIGIN`, `DATABASE_PATH`, `LISTEN_HOST`, `PORT` относятся только к серверу.
Конкретные домены, пути VPS, сети, SSH-данные и Compose находятся в приватном
инфраструктурном репозитории. Не добавляйте их в публичный CI или `VITE_*`.
Подробные команды bootstrap и модель безопасности: [ACCESS_CONTROL](ACCESS_CONTROL.md).

Перед обновлением API сохраняйте резервную копию SQLite через её backup API;
простое копирование файла работающей WAL-базы не является корректной копией.
Статический rollback не откатывает БД. Не удаляйте volume при перезапуске.
