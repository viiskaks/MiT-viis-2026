# Сборка и публикация публичного приложения

Этот репозиторий содержит код MiT-viis-2026, документацию продукта и проверки. Конкретные адреса серверов, SSH-пользователи, host keys, deployment-пути, Docker-сети, TLS-конфигурация и сведения о других проектах относятся к отдельному приватному инфраструктурному репозиторию.

## Публичный CI

[`.github/workflows/ci.yml`](../.github/workflows/ci.yml) запускается при push в `main`, pull request и вручную:

1. Устанавливает Node.js 22 и зависимости через `npm ci`.
2. Запускает ESLint, unit-тесты, TypeScript и production build.
3. Сохраняет `dist/` как артефакт `application-dist` на 7 дней.

Здесь не требуются SSH-ключи, VPS Secrets или токен доступа к приватной инфраструктуре. Проверки используют GitHub-hosted runner и `contents: read`; код из pull request не получает доступ к серверу. Не подключайте self-hosted runner вашего VPS к публичному репозиторию. Причина описана в [GitHub Secure use reference](https://docs.github.com/en/actions/reference/security/secure-use).

## Локальная сборка

```sh
npm ci
npm run build
npm run preview
```

Если npm отсутствует в вашей локальной среде, доступна обёртка `./scripts/npm.sh` при установленном Node и pnpm. `vite preview` нужен только для просмотра результата локально. Для production передайте `dist/` статическому web-серверу — [документация Vite](https://vite.dev/guide/static-deploy.html).

Контракт приложения прост: `index.html`, `assets/` с хешированными файлами и публичные ресурсы. Навигация использует hash (`#/roadmap`), backend для неё не нужен. HTML следует перепроверять при обновлении, хешированные assets можно кэшировать. При размещении в подкаталоге настройте `base` в `vite.config.ts`.

## Приватная публикация

Оператор запускает deployment workflow в приватном инфраструктурном репозитории для выбранного commit этого приложения. Там выполняются проверка и сборка исходников; передача на сервер происходит в отдельном job, которому доступны deployment Secrets. Публичный CI не инициирует приватный workflow и не содержит токен для доступа к нему.

Инструкция оператора, конфигурация web-сервера, секреты подключения, параметры сети, откат и логи публикации находятся только в приватной инфраструктуре. Для этого приложения нет необходимости добавлять VPS Secrets в публичный репозиторий или заводить публичный reusable workflow, который вызывает приватные deployment-шаги.

## Что может быть публичным

Публичны исходники, seed-примеры, собранный JavaScript и CI-артефакты. Никогда не помещайте приватные значения в `src/`, `public/`, `VITE_*`, скриншоты, `.idea/`, документацию или build output. Переменные с префиксом `VITE_` могут попасть в клиентскую сборку: это не хранилище секретов.

Секреты хранятся в настройках Actions приватного репозитория и передаются только нужному job. [GitHub Secrets](https://docs.github.com/en/actions/concepts/security/secrets) скрывает значения в логах, но сама архитектура не должна зависеть только от автоматической маскировки.

Удаление файла из текущей версии Git не удаляет старые коммиты. Если раньше были опубликованы реальные пароли или ключи, их нужно отозвать и отдельно спланировать очистку истории. Наличие общих примеров путей в старой документации само по себе не означает публикацию реальных реквизитов сервера.

Приватный репозиторий скрывает конфигурацию, но публичный сайт по определению раскрывает посетителям свой домен и клиентский код; DNS может раскрывать публичный IP. Это не обещание анонимности хостинга.

## Данные после публикации

Профиль, встречи и программа сохраняются в LocalStorage конкретного origin. Экспортируйте JSON на localhost и импортируйте его на конечном HTTPS-адресе. Публикация новой сборки на том же origin не очищает эти данные. Сменив домен/порт/протокол, вы откроете другое хранилище.

У ментора и менти отдельные копии; обновления через CI не делают приложение совместным в реальном времени. Текст в seed доступен всем посетителям; личные данные из UI не отправляются на сервер автоматически.
